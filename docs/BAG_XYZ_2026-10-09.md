# Return-to-marker loop: bag recording and XYZ analysis

This workflow records a disarmed handheld loop to inspect point-cloud spikes, ghosting, stream gaps, and the return-to-marker error. It needs three terminals: MID360, FAST_LIO, and recording. It does not run MAVROS, SUPER, or the flight controller. If LiDAR/LIO are already running, keep that session rather than starting duplicates.

## Mark and record the route

Mark a repeatable position, height, and heading at the laboratory entrance. Remain stationary for approximately 15 seconds at the start, complete the loop, then return to the same pose and remain stationary for approximately 30 seconds. Do not restart FAST_LIO or reset the origin during the route.

Terminal 1:

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
ros2 launch livox_ros_driver2 msg_MID360_launch.py
```

Terminal 2:

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
source ~/fastlio_ws/install/setup.zsh
ros2 run fast_lio fastlio_mapping --ros-args \
  --params-file "$(ros2 pkg prefix fast_lio)/share/fast_lio/config/mid360.yaml" \
  -p use_sim_time:=false \
  -p publish.map_en:=false \
  -p publish.path_en:=false \
  -p publish.scan_publish_en:=true \
  -p publish.scan_bodyframe_pub_en:=false
```

Initialize stationary and check the timing probe for fresh odometry and no sustained queue growth. Registered-cloud publication requires `scan_publish_en=true`.

Terminal 3:

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
ros2 topic info /cloud_registered
ros2 topic info /Odometry
mkdir -p ~/Downloads/lio_bags
bag_path="$HOME/Downloads/lio_bags/door_loop_$(date +%Y%m%d_%H%M%S)"
ros2 bag record -s sqlite3 -o "$bag_path" \
  /livox/lidar /livox/imu /Odometry /cloud_registered /rosout
```

This recording terminal 3 is unrelated to the MAVROS terminal 3 in the flight runbook. Verify raw-topic names with `ros2 topic list` if the driver configuration differs. Wait for subscriptions before beginning the stationary/loop sequence.

After returning and settling, press Ctrl+C once in the recorder and wait for it to close:

```bash
ros2 bag info "$bag_path"
```

The bag must contain `/cloud_registered` and `/Odometry`; raw sensor topics support later diagnosis. Recording adds load, so monitor LIO timing. Keep the closed bag directory and its `metadata.yaml`.

## Export XYZ

The [deployment helper](../scripts/README.md) installs the categorized exporter into Downloads. For a standalone download:

```bash
xyz_download_dir=$(mktemp -d "$HOME/Downloads/xyz_download_XXXXXX")
if curl -q --noproxy '*' --connect-timeout 10 --max-time 30 -fL \
  'https://raw.githubusercontent.com/Haofei-Hu/Demo_HKU_open-day_SUPER/main/scripts/analysis/bag_to_xyz.py' \
  -o "$xyz_download_dir/bag_to_xyz.py" \
  && python3 -m py_compile "$xyz_download_dir/bag_to_xyz.py"
then
  if [ -f "$HOME/Downloads/bag_to_xyz.py" ]; then
    cp "$HOME/Downloads/bag_to_xyz.py" "$xyz_download_dir/previous.py"
  fi
  cp "$xyz_download_dir/bag_to_xyz.py" "$HOME/Downloads/bag_to_xyz.py"
fi
```

In the recording terminal, where `bag_path` is still set:

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
python3 ~/Downloads/bag_to_xyz.py "$bag_path"
```

In a new terminal, set `bag_path` to the actual bag directory first. Pass the directory rather than a single `.db3` file. The default output is the sibling `<bag_name>_xyz/`; existing output directories are not overwritten. Use `-o` with a new directory for a repeat export.

| Output | Contents |
| --- | --- |
| `cloud_all.xyz` | All registered world-frame cloud points, including finite spikes and repeated scans |
| `cloud_start.xyz`, `cloud_end.xyz` | First/last five seconds for colored overlay comparison |
| `cloud_first_frame.xyz`, `cloud_last_frame.xyz` | First/last usable individual cloud |
| `cloud_frames.csv` | Frame timestamps, finite point counts, and row offsets |
| `trajectory.xyz`, `trajectory.csv` | Odometry trajectory, timestamps, and orientations |
| `report.json` | Topic timing, timestamp anomalies, stationary-window statistics, and return error |

Open start/end clouds in CloudCompare with different colors. Inspect walls for ghosting, isolated spikes, and displaced surfaces before applying ICP. Alignment would remove the return error being measured. The merged cloud is a stack of scans rather than an optimized map; only NaN/Inf cloud points are removed, with no voxel or outlier filtering.

## Interpret the results

Timing statistics distinguish bag-record intervals, source-header intervals, non-increasing timestamps, and record-minus-header age. The default `--gap 0.5` highlights large offline intervals; it is not a flight acceptance threshold. Gaps can originate in sensing, publishing, DDS, or recorder overload, so compare them with timing-probe evidence.

Return metrics compare the first/last five-second position means and report XYZ, horizontal/3D error, yaw change, stationary radius, and the final three windows. Interpret these as return error only when both windows are stationary at the same marked pose. Short/overlapping windows or changed odometry frames do not yield valid closure metrics.

Odometry refers to the LIO IMU origin; registered clouds use the LIO world. Neither automatically becomes floor-relative FC height. Matching start/end orientation reduces lever-arm ambiguity without calibrating extrinsics. FAST_LIO has no loop-closure optimizer; returning to a stable estimate does not imply correction back to the origin.

The exporter passed synthetic-bag checks for known return bias, a 1.1-second gap, timestamp regression, finite spike preservation, frame changes, and overwrite refusal. Actual loop performance remains to be measured.

For flight recordings, use the [complete flight stack](FIRST_HOVER_2026-10-09.md) and an additional recorder. Add `/mavros/state`, `/mavros/estimator_status`, `/mavros/extended_state`, `/mavros/rc/in`, `/mavros/local_position/pose`, `/mavros/vision_pose/pose_cov`, and `/super_debug/first_hover_target`. The three-terminal handheld workflow itself does not control the aircraft.
