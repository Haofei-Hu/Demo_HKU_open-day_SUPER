# 门口绕圈：三终端录包、XYZ 和返回误差

目标是查看点云毛刺、重影、断流和回到标记后的定位误差。这是未解锁手持测试，三个终端分别运行 MID360、FAST_LIO、录包；不需要 MAVROS、SUPER 或悬停程序。已有雷达／LIO 节点时沿用该会话，避免重复启动。录包终端的“3”只属于本节，不是悬停工作流的 MAVROS 终端 3。

## 标记与录制

在实验室门口标记雷达／机体的位置、高度和朝向。开始时静止约 15 秒，随后绕一圈，回到相同标记、相同高度和朝向后静止约 30 秒。中途不重启 FAST_LIO，不改变零点。记录路径和实际动作，方便区分返回摆放偏差与定位漂移。

终端 1：

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
ros2 launch livox_ros_driver2 msg_MID360_launch.py
```

终端 2：

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
source ~/fastlio_ws/install/setup.zsh
ros2 run fast_lio fastlio_mapping --ros-args \
  --params-file "$(ros2 pkg prefix fast_lio)/share/fast_lio/config/mid360.yaml" \
  -p use_sim_time:=false \
  -p publish.map_en:=false \
  -p publish.path_en:=false \
  -p publish.scan_publish_en:=true \
  -p publish.scan_bodyframe_pub_en:=false
```

初始化放稳，确认 timing probe 位姿新鲜、队列没有持续积压；`scan_publish_en=true` 才有世界点云。这里不修改频率或测量时间戳。

终端 3：

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
ros2 topic info /cloud_registered
ros2 topic info /Odometry
mkdir -p ~/Downloads/lio_bags
bag_path="$HOME/Downloads/lio_bags/door_loop_$(date +%Y%m%d_%H%M%S)"
ros2 bag record -s sqlite3 -o "$bag_path" \
  /livox/lidar /livox/imu /Odometry /cloud_registered /rosout
```

原始 Livox 话题名以当前驱动为准；如果修改过，先用 `ros2 topic list` 核对。录制期间等终端显示已经订阅，再开始静止和绕圈。回到标记并静止后，在录包终端 **Ctrl+C 一次，等它完成关闭**：

```bash
ros2 bag info "$bag_path"
```

必须有 `/cloud_registered` 和 `/Odometry` 的记录。原始传感器消息用于后续复查，导出器只要求前面两项。磁盘写入和录包会增加负载，观察当前 timing probe；完整 bag 保留在本机。

## 导出 XYZ

已有分类仓库时，用 [部署工具](../scripts/README.md) 将脚本复制到 Downloads。只下载导出器也可以，下面命令不启动 ROS 节点：

```bash
xyz_download_dir=$(mktemp -d "$HOME/Downloads/xyz_download_XXXXXX")
if curl -q --noproxy '*' --connect-timeout 10 --max-time 30 -fL \
  'https://raw.githubusercontent.com/Haofei-Hu/Demo_HKU_open-day_SUPER/main/scripts/analysis/bag_to_xyz.py' \
  -o "$xyz_download_dir/bag_to_xyz.py" \
  && python3 -m py_compile "$xyz_download_dir/bag_to_xyz.py"
then
  if [ -f "$HOME/Downloads/bag_to_xyz.py" ]; then
    cp "$HOME/Downloads/bag_to_xyz.py" "$xyz_download_dir/previous.py"
  fi
  cp "$xyz_download_dir/bag_to_xyz.py" "$HOME/Downloads/bag_to_xyz.py"
fi
```

在刚才录包终端，`bag_path` 仍然保留时执行：

```bash
source /opt/ros/humble/setup.zsh
source ~/ws_livox/install/setup.zsh
python3 ~/Downloads/bag_to_xyz.py "$bag_path"
```

换过终端则把 `bag_path` 设为实际 bag 目录，目录内应有 `metadata.yaml`。不要传单个 `.db3` 文件。默认输出同级 `<bag名>_xyz`，拒绝覆盖已有目录；想重复分析可使用 `-o` 指定新的目录。

| 输出 | 内容 |
| --- | --- |
| `cloud_all.xyz` | 全程世界点云 XYZ，保留重复点和有限值毛刺 |
| `cloud_start.xyz`、`cloud_end.xyz` | 首／尾各 5 秒点云，便于分别着色叠加 |
| `cloud_first_frame.xyz`、`cloud_last_frame.xyz` | 首／末单帧 |
| `cloud_frames.csv` | 每帧时间戳、点数、有效点及帧记录 |
| `trajectory.xyz`、`trajectory.csv` | `/Odometry` 轨迹与时间、姿态记录 |
| `report.json` | 话题间隔、时间戳异常、首尾静止均值差及尾部稳定性 |

用 CloudCompare 打开 start／end，分别赋不同颜色，查看墙面重影、离群尖点和局部错层。第一次比较保留原坐标，先不要运行 ICP，否则会把要观察的返回误差对齐掉。`cloud_all.xyz` 是多帧堆叠，重复点正常，不是优化后的全局地图；导出只删除 NaN／Inf，没有降采样或自动去毛刺。

## 如何判断

`report.json` 同时统计录包收到消息的间隔、源 header 间隔、时间倒退，以及录包时间减 header 时间。默认 `--gap 0.5` 只是突出较大间隔的诊断阈值，不是飞行验收限值。录包间隔异常可能来自发布、DDS、录制负载；要结合 header 和 timing probe 判断，不能直接证明传感器断了。

返回误差使用首／尾各 5 秒位置平均值，列出 XYZ／水平／三维差和 yaw 差，同时检查窗口内摆动与最后几个窗口。只有真实回到相同标记、高度、朝向并保持静止，才可解释为返回误差。时长太短、首尾窗口重叠或坐标帧改变时不报告有效闭合结果。

轨迹原点是 FAST_LIO 的 IMU 原点，点云是已注册的世界点云；它们不是自动换算成飞控中心的离地高度。相同姿态的返回比较可以减少安装杆臂影响，但不能代替外参标定。FAST_LIO 本身没有回环优化；回来后稳定不等于主动收敛到原点，存在小误差或重影也需结合摆放误差评估。

当前尚未收到实采 bag 或绕圈误差，不预填结果。导出器已通过合成 bag 验证，包括已知返回偏差、1.1 秒断口、时间倒退、有限毛刺保留、帧变化以及拒绝覆盖；真实雷达负载和环境仍需这次测试。

如果需要记录悬停的完整 MAVROS 状态，沿用 [终端 1–11 工作流](FIRST_HOVER_2026-10-09.md)，再另开录包窗口加入 `/mavros/state`、`/mavros/estimator_status`、`/mavros/local_position/pose`、`/mavros/vision_pose/pose_cov`、`/super_debug/first_hover_target`。三终端手持方案本身不控制飞机。
