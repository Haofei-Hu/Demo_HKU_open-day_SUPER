Concurrent 30-second native vision sampling remained fresh: maximum header age 60 ms and receive gap 41 ms. The managed `low-speed-3d` planner now creates a separate session YAML before launch. A read-only helper captures three seconds of fresh stationary raw odometry while connected, disarmed and grounded, then freezes a grid-aligned vertical offset for that core session. Only virtual ground, virtual ceiling and initial map-centre Z shift. At the recorded height, the shift is -1.2 m: configured ground/ceiling become -2.7/2.3 m and map centre Z becomes 0.3 m; effective bounds become -2.3/1.7 m. The vertical span is preserved. Source YAML, point clouds, robot radius, velocity/acceleration, goal coordinates and physical 10 cm flight/reference margins are unchanged.

The reference record is retained in the current session log directory. Repeated planner starts reuse it instead of accumulating offsets or following drift. A changed raw publisher/alignment or raw ground-height change over 0.10 m refuses reuse. A new core session gets its own record. Creating a session profile is not physical floor calibration, map relocalization or a localization-drift repair.

Five isolated DDS capture cases covered healthy input, movement, raw dropout, arming and duplicate publishers. ## Automatic ground workflow

The [automatic ground runner](AUTOMATED_GROUND_TEST.md) now performs a fresh core startup, structured alignment capture, quality-checked quaternion application, session-map creation, one disarmed audit with concurrent input sampling, a six-second endpoint hold and a final readiness snapshot. It sources the installed workspace environments itself and writes per-stage logs plus JSON reports. A restart must be explicitly requested; failures stop the sequence without replaying the goal, restarting nodes or widening limits. Preparation and audit are separate stages for later supervised-flight integration; the current runner has no flight execution option.

Initial validation covered 11 orchestration/quality/locking/failure cases, two alignment-estimator cases, 38 manager cases and three layout/install cases. Isolated DDS checks ran the real survey subprocess for valid and insufficient samples, verified output overwrite refusal, and covered six audit-observer cases: nominal hold, vision dropout, duplicate source, unexpected native writer, controller stop and lost acknowledgement. Each observer case sent exactly one audit request and no mode/arming requests. The completed aircraft audit above used the manually sequenced workflow.

The first automatic aircraft run `20261015_163235_275559` stopped at `vision` before launching it: Python 3.10 rejected the interleaved command options and quaternion positionals. Its 639-pair survey was valid (maximum spread 0.604 degrees, body age 38.3 ms), so no calibration change was required. This error reproduces under Ubuntu Python 3.10 even though the same invocation parses on the development host's Python 3.12. The runner now places shared options before the action and uses `--` before quaternion values; the manager inserts its ROS bootstrap flag before that separator. New checks parse the actual generated command, including the full aircraft quaternion and negative scientific notation, rather than substituting a fake action. The Python 3.10 regression passed 12 runner, 39 manager and three layout tests. The corrected automatic workflow still requires an aircraft retest.
