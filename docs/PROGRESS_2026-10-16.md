# Integration progress — October 16, 2026

The acceptance target is now the complete demonstration: 2 m takeoff, 4.5 m outbound along the long venue edge, return, six-second home hover and confirmed landing/disarming. The new automatic test starts a fresh managed session, captures the alignment without manual quaternion entry and saves a single scoped result. See [the runbook](DEMONSTRATION_MISSION.md).

## Implemented behavior

The complete supervisor owns exactly one outbound and one return goal. It retains the 2 m/s and 1 m/s² planner caps and 10 cm per-axis requirements. Reports require all eight stages in order; an outbound-only result cannot pass. Landing remains owned by PX4; the mission observes fresh pose, home XY error and landed/disarmed feedback before accepting completion. Whole-aircraft boundary checks use measured FC-relative extents and a variable takeoff position inside the outer 5.8 × 2.8 × 2.8 m venue. Missing measurements remain explicit. A synthetic geometry option enables virtual rehearsal without claiming physical clearance.

The automatic ground entrypoint checks real localization, freezes the occupied map and paired geometry, then runs real SUPER against that static model in a private localhost-only ROS domain with a virtual vehicle and FC. It has no actual-aircraft flight initiation option. A separate explicit logic-only mode uses a synthetic planner and labels that scope. Real-SUPER failure cannot silently select this substitute.

Two integration assumptions were corrected. Committed SUPER trajectories can end at intermediate backup braking stops, so stage replacement no longer implies navigation completion or a relocated goal. FC pose samples are compared against sent position/velocity references at their unchanged measurement timestamps, avoiding comparison of past feedback with future targets. Stale references, real discontinuities, overspeed and errors above 10 cm still fail.

The standalone hover artifact now preserves selected canonical source text instead of using Python-version-dependent AST formatting. Python 3.10 and the development interpreter can perform the same exact artifact check. The original short hover/audit limits and default behavior remain separate. The vision-chain sampling CLI now returns nonzero when it prints a failed freshness result, preventing automated false success.
